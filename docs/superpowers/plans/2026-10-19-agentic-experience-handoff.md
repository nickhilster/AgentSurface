# Agentic Experience Handoff Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user inspect the selected product's real first-party page inside the agentic application they are using, with honest fallback behavior when that host cannot open it in-app.

**Architecture:** The website-side AgentSurface model declares and validates canonical destinations. A host-neutral handoff contract carries an exact destination and asks the user's agentic application to open it; a separate host adapter performs the actual navigation and reports the surface used. The site never forces a browser or claims host support.

**Tech Stack:** TypeScript, Node.js ESM, Vitest. Host-specific APIs remain behind host adapters and are selected only after the user names a supported target application.

**Spec:** docs/SPEC.md, especially “User experience handoff,” “Agent-facing interaction flow,” “Security, privacy, and safety,” and “Delivery phases and success criteria.” Depends on docs/superpowers/plans/2026-10-19-catalog-discovery.md for product IDs and canonical item destinations.

## Global Constraints

- “The host, not the website, decides how to present it and retains user control.”
- “The page opened must be the website's real experience, not merely an agent-generated text summary or a copied card.”
- “Only same-site canonical public destinations may be generated by default.”
- “The host must not claim that an embedded experience is available until it confirms that presentation outcome.”
- “If the host has no embedded experience, the agent can present a direct canonical link for the host to open externally.”
- “Item identity is preferred over copying the full natural-language conversation into a URL.”
- “URLs and handoff references must not contain credentials, private user attributes, or hidden tracking payloads.”
- “Host navigation is user-controlled and must not bypass browser security, authentication, or permission prompts.”

## Review Focus

- An untrusted or cross-origin destination is rejected unless explicitly configured; pin with src/lib/destinations.test.ts::rejectsUnapprovedOrigin.
- A successful request is not mislabeled as an in-app open before host confirmation; pin with src/handoff/handoff.test.ts::reportsOnlyConfirmedPresentation.
- Unsupported embedded browsing returns a clear external fallback; pin with src/handoff/handoff.test.ts::unsupportedHostGetsCanonicalFallback.
- Handoff context contains only the item identity and owner-allowlisted non-sensitive fields; pin with src/handoff/handoff.test.ts::dropsUnapprovedContext.
- The resolved destination is the real canonical product page, not a Markdown alternate; pin with src/handoff/handoff.test.ts::usesCanonicalHtmlDestination.
